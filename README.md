# أسانيد (Asanid)

منصة ذكاء اصطناعي تُجري مع العميل محادثة استقصائية مُوجَّهة حول قضيته، تستلم منه المستندات الداعمة، ثم تصوغ له **لائحة الدعوى** (ولاحقًا: مذكرة جوابية، مذكرة دفاع، مذكرة استئناف، التماس إعادة نظر) استنادًا إلى نصوص الأنظمة السعودية ذات العلاقة — نظام المرافعات الشرعية، نظام المعاملات المدنية، نظام الإثبات، نظام العمل، نظام المحاكم التجارية، وأنظمة أخرى تُضاف تباعًا.

> ⚠️ **تنويه إلزامي**: مخرجات المنصة مسودات داعمة أولية لتوفير الوقت والجهد، وليست استشارة قانونية ولا بديلاً عن محامٍ مرخّص. يجب أن يراجعها ويعتمدها محامٍ مرخّص أو مستشار قانوني قبل أي استخدام فعلي أمام أي جهة قضائية. هذا التنويه يظهر في كل مستند تُصدره المنصة.

## حالة المشروع

هذا هو **النموذج الأولي (MVP)** ونطاقه الحالي:
- توليد نوع مستند واحد فقط: **لائحة الدعوى**
- الباك-إند وواجهة الويب (لا يوجد تطبيق جوال بعد)
- قاعدة معرفة قانونية جاهزة الهيكلة لكن **فارغة من النصوص الكاملة** — تحتاج تعبئة (راجع [`docs/LEGAL_KNOWLEDGE_BASE.md`](docs/LEGAL_KNOWLEDGE_BASE.md))
- بوابة دفع/اشتراك **غير مُفعّلة فعليًا** (Stub) — الجدول والمنطق جاهزان، ينقصهما ربط ببوابة دفع سعودية حقيقية (Moyasar/PayTabs/Tap)

راجع [`docs/ROADMAP.md`](docs/ROADMAP.md) لما هو قادم.

## البنية

| المسار | الغرض |
|---|---|
| [`database/schema.sql`](database/schema.sql) | مخطط Postgres الكامل: المستخدمون، الباقات، الاشتراكات، القضايا، محادثة الاستقصاء، المستندات المرفوعة، قاعدة المعرفة القانونية (الأنظمة والمواد)، المستندات المولّدة واستشهاداتها |
| [`backend/`](backend/README.md) | خدمة Node.js + TypeScript + Express: المصادقة، الاشتراكات، محرك الاستقصاء، توليد المستندات، تصديرها Word |
| [`web/`](web/README.md) | واجهة ويب Next.js: صفحة الباقات، محادثة الاستقصاء، عرض/تنزيل المستند المولّد |
| [`legal-kb/`](legal-kb/README.md) | ملفات تلقين قاعدة المعرفة القانونية (JSON) وسكربت تحميلها لقاعدة البيانات |
| [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md) | شرح تفصيلي للمعمارية وتدفق البيانات وقرارات التصميم |
| [`docs/LEGAL_KNOWLEDGE_BASE.md`](docs/LEGAL_KNOWLEDGE_BASE.md) | كيف تُضاف نصوص الأنظمة الكاملة، وضوابط منع الاستشهاد المُختلَق |
| [`docs/ROADMAP.md`](docs/ROADMAP.md) | خارطة الطريق: بقية أنواع المذكرات، تكامل ناجز، التطبيق الجوال |

## البدء السريع

```bash
# 1) قاعدة البيانات (Postgres 14+ أو Supabase)
psql "$DATABASE_URL" -f database/schema.sql

# 2) الباك-إند
cd backend
npm install
cp .env.example .env   # عبّئ DATABASE_URL و AI_PROVIDER ومفاتيحه
npm run dev            # يعمل افتراضيًا على :4000

# 3) قاعدة المعرفة القانونية (بيانات تمهيدية placeholder فقط)
npm run seed:legal-kb

# 4) واجهة الويب
cd ../web
npm install
cp .env.example .env.local   # NEXT_PUBLIC_API_URL=http://localhost:4000
npm run dev            # يعمل افتراضيًا على :3000
```

## المعمارية باختصار

```
العميل (ويب) ──► Next.js (web/)
                     │  fetch
                     ▼
              Express API (backend/src/server.ts)
                     │
        ┌────────────┼─────────────────┐
        ▼            ▼                 ▼
  intakeEngine   legalKnowledgeBase   aiProvider (Claude / OpenAI)
        │            │                 │
        └──────► caseDocumentGenerator ◄┘
                     │
                     ▼
              docxBuilder → مستند Word قابل للتنزيل
                     │
                     ▼
              Postgres (database/schema.sql)
```

كل استشهاد قانوني في المستند المولَّد **يجب** أن يكون مرتبطًا بمادة موجودة فعليًا في `legal_articles` — النظام مصمم لرفض أي استشهاد لا يجده في السياق المُسترجَع من قاعدة المعرفة، بدل السماح للنموذج باختلاق أرقام مواد (راجع تفاصيل الضمانة في `docs/LEGAL_KNOWLEDGE_BASE.md`).
