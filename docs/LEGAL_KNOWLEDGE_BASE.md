# قاعدة المعرفة القانونية

## الحالة الحالية

المخطط جاهز بالكامل (`legal_regulations`, `legal_articles`) لكنه **فارغ من النصوص الرسمية الكاملة**. الموجود حاليًا في `legal-kb/seed/` مجرد **أمثلة توضيحية (placeholders)** لعدد قليل من المواد لاختبار تدفق النظام برمجيًا فقط — **لا يجوز استخدامها كمصدر قانوني حقيقي بأي حال**، ويجب استبدالها بالنصوص الرسمية قبل أي استخدام فعلي.

## الأنظمة المستهدفة (حسب طلب المشروع)

| النظام | الاستخدام في المنصة | الأولوية |
|---|---|---|
| نظام المرافعات الشرعية | إجراءات رفع الدعوى، شكل اللائحة، المواعيد، الطعون | أساسي — كل قضية |
| نظام الإثبات | وسائل الإثبات (البيّنة، الإقرار، اليمين، القرينة) المرتبطة بالمستندات الداعمة | أساسي — كل قضية |
| نظام المعاملات المدنية | السند النظامي للحقوق والالتزامات المدنية (عقود، ضمان، تعويض...) | أساسي — القضايا المدنية |
| نظام العمل | القضايا العمالية (فصل تعسفي، مستحقات، مكافأة نهاية خدمة) | مشروط — عندما يُجيب العميل بأنه موظف |
| نظام المحاكم التجارية | القضايا التي يكون أحد أطرافها جهة تجارية | مشروط — عندما تتضمن القضية طرفًا تجاريًا |
| أنظمة أخرى (تُحدَّد لاحقًا) | حسب نوع القضية | تُضاف تباعًا دون تعديل بنيوي |

## كيفية إضافة نصوص نظام كامل

1. أضف صفًا في `legal_regulations`:
   ```sql
   insert into legal_regulations (code, name_ar, issued_by, royal_decree_ref, effective_date, source_url)
   values ('sharia_procedure_law', 'نظام المرافعات الشرعية', 'وزارة العدل', 'م/1 وتاريخ ...', '...', 'https://laws.moj.gov.sa/...');
   ```
2. لكل مادة، أضف صفًا في `legal_articles` مرتبطًا بـ `regulation_id`:
   ```sql
   insert into legal_articles (regulation_id, article_number, article_text, topic_tags)
   values ((select id from legal_regulations where code = 'sharia_procedure_law'), '39',
           'نص المادة كاملاً وحرفيًا كما ورد في المصدر الرسمي...',
           array['لائحة الدعوى','شكل الدعوى']);
   ```
3. أو استخدم السكربت الجماعي: ضع ملف JSON بنفس بنية `legal-kb/seed/sharia_procedure_law.sample.json` في `legal-kb/data/` (مجلد غير موجود بعد عمدًا — أنشئه عند توفر النصوص الحقيقية)، ثم:
   ```bash
   cd backend && npm run seed:legal-kb -- --file ../legal-kb/data/sharia_procedure_law.json
   ```

**يجب دائمًا نقل نص المادة حرفيًا من المصدر الرسمي** (البوابة القانونية لوزارة العدل `laws.moj.gov.sa`، أو جريدة أم القرى) — لا يُسمح بإعادة الصياغة أو التلخيص عند الإدخال، لأن هذا النص هو ما سيُستشهد به حرفيًا في المستندات المولَّدة.

## ضمانة منع الاستشهاد المُختلَق (Anti-Hallucination Guardrail)

هذه أهم نقطة تصميمية في كامل المشروع، لأن استشهادًا قانونيًا مُختلَقًا في لائحة دعوى حقيقية ضرر مباشر للعميل ومسؤولية على المنصة.

الآلية في `caseDocumentGenerator.ts`:

1. **الاسترجاع أولاً**: `legalKnowledgeBase.retrieveRelevantArticles()` يجلب من قاعدة البيانات فقط (لا يعتمد على معرفة النموذج الداخلية) قائمة مواد مرشّحة حسب نوع القضية والأنظمة المفعَّلة.
2. **حصر السياق**: هذه القائمة فقط هي ما يُمرَّر للنموذج ضمن الـ Prompt، مع تعليمة نظامية صريحة: *"استشهد فقط بالمواد الواردة أدناه بنفس رقمها ونصّها، ولا تذكر أي رقم مادة أو نظام غير موجود في هذا السياق. إن لم تجد سندًا كافيًا، اذكر ذلك صراحة بدل اختلاق استشهاد."*
3. **التحقق البرمجي بعد التوليد**: `validateCitations()` يقارن كل استشهاد ورد في مخرجات النموذج مع القائمة المُسترجَعة فعليًا؛ أي استشهاد لا يطابق (رقم نظام + رقم مادة) يُرفض المستند برمّته ولا يُصدَّر، ويُرجع خطأ للواجهة بدل عرض مستند فيه استشهاد غير موثوق.
4. **فراغ قاعدة المعرفة حاليًا يعني أن هذه الضمانة ستمنع توليد أي مستند فعليًا** حتى تُعبَّأ المواد الحقيقية — وهذا سلوك مقصود، لا عطل. راجع رسالة الخطأ `NO_GROUNDED_ARTICLES_FOUND`.

## البحث/الاسترجاع الحالي مقابل خطة الترقية

الاسترجاع في الـ MVP بسيط (مطابقة كلمات مفتاحية `topic_tags` + `regulation code`)، لا يستخدم تضمينات (embeddings). عمود `embedding` محجوز مسبقًا في `legal_articles` (نوع `vector` عبر امتداد `pgvector`) لترقية لاحقة لاسترجاع دلالي (RAG حقيقي) دون تعديل بنيوي إضافي — فقط تفعيل الامتداد وتعبئة العمود.
